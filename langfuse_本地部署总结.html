1. 整体流程总览

目标是把可观测性从 LangSmith 切到本地自建 Langfuse：数据留在本机， 投顾脚本通过 Callback 上报 Traces，原 LangSmith 脚本保持不动。

2. 本地部署全过程

2.1 目录规划

路径用途实际结果
H:\Langfuse Langfuse 源码与 docker-compose 已用 git clone ... . 避免重复子目录
H:\DockerData Docker 磁盘镜像（建议） 目录已创建；可在 Docker Desktop 中将 Disk image 指到此处
H:\Docker Desktop 希望的安装目录 winget 实际装到了默认的 C:\Program Files\Docker

2.2 分步操作

  1. 安装 Docker Desktop
    通过 winget 安装 Docker.DockerDesktop。安装后客户端可用，但引擎依赖 WSL2。
  2. 启用并安装 WSL
    DISM 启用 Microsoft-Windows-Subsystem-Linux 与 VirtualMachinePlatform； 重启后仍需 winget install Microsoft.WSL，再启动 Docker Desktop。
  3. 克隆 Langfuse（无嵌套文件夹） 
    New-Item -ItemType Directory -Force -Path H:\Langfuse | Out-Null
Set-Location H:\Langfuse
git config --global core.longpaths true
git clone https://github.com/langfuse/langfuse.git .
  4. 启动服务 
    Set-Location H:\Langfuse
docker compose up -d
    首次会拉取 postgres / redis / clickhouse / minio / langfuse-web / worker 等镜像，耗时较长。
  5. 初始化账号与密钥
    打开 http://localhost:3000 → Sign up → 创建 Organization / Project → Settings → API Keys，获取 pk-lf-... 与 sk-lf-...。
    「Enable AI powered features」本地试用可保持关闭。
  6. 接入投顾脚本（新文件，不改原脚本）
    新文件：1-hybrid_wealth_advisor_langgraph_langfuse.py
    用 Langfuse CallbackHandler 替代 LangSmith，并在脚本内关闭 LANGCHAIN_TRACING_V2，避免重复上报。
验收标准：浏览器访问 localhost:3000 返回可用页面；跑脚本后项目 Traces 中出现本次调用链。

3. 过程中遇到的问题

问题现象原因 / 处理
Docker 未安装 docker 命令找不到 winget 安装 Docker Desktop；直连官网安装包曾 Connection reset
WSL 未就绪 Docker 客户端在，引擎连不上；重启后仍提示未安装 WSL DISM 启用功能 + 重启 + winget install Microsoft.WSL
Git 路径过长 clone 失败：Filename too long git config --global core.longpaths true 后 git reset --hard
镜像拉取失败 / 很慢 auth.docker.io EOF；反复 Downloading 网络不稳，多次 docker compose up -d 重试后成功
Langfuse 401 Unauthorized Agent 正常跑，但刷 Failed to export spans ... 401 只设了 pk/sk，未把 LANGFUSE_BASE_URL 写回环境；SDK 可能打到云端。已在脚本中强制写回 env 并显式传 base_url
安装路径未按预期 希望装到 H:\Docker Desktop winget 落到默认 C 盘路径；程序位置影响小于 Disk image 位置
401 不影响投顾问答结果，只影响 Traces 是否进 Langfuse。业务能跑 ≠ 观测已通。

4. 注意事项

  • 本地自建必须配置 LANGFUSE_BASE_URL=http://localhost:3000，不要用云端地址。
  • 公钥 pk-lf-、私钥 sk-lf- 成对使用，复制时勿带空格/换行；Secret 通常只显示一次。
  • 环境变量优先写在「用户变量」，改完后新开终端再跑脚本。
  • 占空间的是 Docker 数据盘，建议在 Docker Desktop 将 Disk image 指到 H:\DockerData。
  • 克隆到 H:\Langfuse 时用末尾 .，避免 H:\Langfuse\langfuse 重复目录。
  • Windows 拉 Langfuse 仓库务必开启 core.longpaths。
  • 端口占用：UI 默认 3000，MinIO 9090；冲突需改 compose 映射并同步改 Base URL。
  • 停服务用 docker compose down；带 -v 会删数据卷，本地账号与 Traces 会清空。
  • 原课件 1-...langsmith.py 未改；Langfuse 版是独立新文件。

5. 后续再次调用 Langfuse 的方法

5.1 确认服务在跑

Set-Location H:\Langfuse
docker compose ps
# 若未运行：
docker compose up -d

5.2 设置环境变量（PowerShell）

$env:LANGFUSE_PUBLIC_KEY="pk-lf-你的公钥"
$env:LANGFUSE_SECRET_KEY="sk-lf-你的私钥"
$env:LANGFUSE_BASE_URL="http://localhost:3000"
# 通义密钥若系统已配置可省略
$env:DASHSCOPE_API_KEY="你的通义密钥"

5.3 运行投顾脚本

python .\1-hybrid_wealth_advisor_langgraph_langfuse.py

启动时应看到：

LANGFUSE_ENABLED= True
LANGFUSE_BASE_URL= http://localhost:3000
Langfuse 追踪已启用

5.4 查看追踪

浏览器打开 http://localhost:3000 → 进入对应 Project → Traces。

5.5 快速自检密钥（可选）

python H:\Langfuse\check_langfuse_keys.py
# 期望输出含 RESULT=VALID

5.6 代码侧接入要点（已在新脚本中）

from langfuse import Langfuse
from langfuse.langchain import CallbackHandler

# 写回 env + 显式 base_url，避免 401
os.environ["LANGFUSE_BASE_URL"] = "http://localhost:3000"
client = Langfuse(public_key=..., secret_key=..., base_url=...)
handler = CallbackHandler()

agent.invoke(state, config={
    "callbacks": [handler],
    "tags": ["wealth-advisor", "hybrid-agent"],
    "metadata": {"customer_id": "..."},
    "run_name": "wealth-advisor-..."
})
client.flush()  # 短脚本必须 flush
